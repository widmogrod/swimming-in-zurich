# Delete the legacy geo pipeline — one builder, one gold schema

**What & why.** Plan C of the [[techdebt-remediation-roadmap]] (the largest deletion; a product
decision the owner signed off): the pre-spine `raw → silver → gold` id path was a parallel second
route to a gold row that the identity spine + one offline builder made redundant, and Plan B left
the `facility` table write-only-dead. Plan C deletes both. Geo now flows only via the committed
`catalog.json`.

## What exists now (verified live: build → scrape-gold → scrape-lanes → serve)

- **One offline builder** — `swimzh build` (`etl/build.build_store`) is the sole path to a gold row;
  `build-catalog`/`scrape-gold`/`scrape-lanes` layer onto it. `build-gold`, `etl/pipeline`, `etl/raw`,
  `silver.reconcile`, `registry.resolve_*` are **deleted** (`attach_lane_plans` kept).
- **Gold schema = `{pool, pool_alias, pool_xref, calendar}`** — the `facility` table, `write_facilities`
  (both call sites), `etl/gold.write_gold`, and the test-only `load_catalog` are **deleted**. The
  schedule payload lives in `pool.facility_doc`; `curation_status` is derived at read.
- **Geo provenance = committed catalog** — WFS coordinates flow only via `data/catalog.json`
  (regenerated by `build-catalog`), stamped onto `facility_doc` offline (Plan B1). No live WFS merge.
- **Cutover guard** off `pool_alias` (C1) — every legacy id resolves to one canonical pool,
  independent of the deleted `resolve_name`.
- **Coverage floor ratcheted** 91 → 95 (real 95.61% after the deletions).

## Live proof

CLI subcommands = `{build, build-catalog, scrape-gold, scrape-lanes}`; gold DB tables =
`{calendar, pool, pool_alias, pool_xref}`; `/swim` serves options + live uncurated statuses; City
shows full lane availability — all off the one `pool.facility_doc` read path.

## Backlog

None new. Program-wide remainder: the D/E roadmap items (resilient reconcile; calendar pyright) and
the deferred structural items (full row-normalization, snapshots, Dagster).
