# Plan C — Delete the legacy geo pipeline (and the now-dead `facility` table)

## Context

Plan C of the [[techdebt-remediation-roadmap]]: the largest deletion, low CODE risk, an explicit
**product decision** (owner picked A/B/C → sign-off given). The pre-spine `raw → silver → gold` id path
(`etl/pipeline`, `etl/raw`, `silver.reconcile`, `registry.resolve_*`, `build-gold`) is a parallel
second route to a gold row that the identity spine + one offline builder made redundant. Deleting
`build-gold` also makes the `facility` table (which [[retire-facility-table]] left write-only-dead) and
`write_facilities`/`write_gold`/`etl.gold` genuinely dead, so C removes them too.

**Depends on [[retire-facility-table]] (full Plan B)** — not just B1. B flips reads/enrichment onto
`pool.facility_doc` and stamps geo offline (B1); only then is deleting `build-gold`'s live WFS merge
safe and the `facility` table dead.

## Design (signature altitude)

- **One builder.** `etl/build.build_store` (called by `swimzh build`, offline) is **kept** — it already
  IS the one offline builder the design names. Only the *parallel* pipeline is deleted; there is no
  "fold build_store away" (it has 5 live importers incl. the web-app test fixtures — inlining it is pure
  churn). Network commands (`scrape-gold`, `scrape-lanes`, `build-catalog`) layer onto the built store.
- **Geo provenance = committed WFS catalog.** WFS coordinates live in the committed, reviewable
  `data/catalog.json` (regenerated by `build-catalog`, which is **kept**), stamped onto facilities
  offline (Plan B1). No live WFS merge at gold-build time. Deleting `build-gold` is a **source shift**
  (WFS-at-build → committed-catalog), not a geo drop — `/swim` distance keeps working. A future
  scheduled refresh, if ever wanted, returns as an additive `refresh` skin (open-question #2).
- **Surgical, not file-level, deletion.** `silver.reconcile` and `attach_lane_plans` share
  `etl/silver.py`; only `reconcile` is deleted (`attach_lane_plans` is KEPT and does not depend on it),
  and its now-unused imports (`Dataset`, `GeoPool`) are cleaned. `tests/etl/test_silver.py` keeps its 6
  `attach_lane_plans` tests and drops only the 2 `reconcile` tests.

## Out of scope

- `attach_lane_plans` (KEEP), `build-catalog` (KEEP), `etl/build.build_store` (KEEP).
- Snapshots / `refresh`/`verify` (#6b) and Dagster (#6c).

- **2026-07-20 — Open-question #2 resolved (owner picked A/B/C = sign-off).** Deleting `build-gold`
  removes the only live WFS geo-refresh (it is tested, not dead). Confirmed: geo flows permanently via

- **2026-07-20 — Review adjustments (pre-implementation).** A draft review corrected the first draft:
  (1) `etl/build.build_store` is KEPT (it IS the offline builder, 5 live importers incl. web-app
  fixtures) — the "fold build_store into build" language was struck; only `pipeline`/`raw`/`build-gold`

  because `build-gold` still wrote it) → new slice C3. (3) `silver.reconcile` deletion is surgical

  lands the offline geo parity on the read path).
