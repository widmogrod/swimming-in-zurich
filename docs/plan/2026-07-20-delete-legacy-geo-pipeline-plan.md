# Plan C — Delete the legacy geo pipeline

## Context

Plan C of the [[techdebt-remediation-roadmap]]: the largest deletion, low CODE risk, and an explicit
**product decision** (owner picked A/B/C → sign-off given). The pre-spine `raw → silver → gold` id
path (`etl/pipeline`, `etl/raw`, `silver.reconcile`, `registry.resolve_*`, `build-gold`) is now a
parallel second route to a gold row that the identity spine + one offline builder made redundant.
Collapse to the ONE offline builder the design names; geo flows via the committed `catalog.json`
(regenerated with `build-catalog`), stamped onto facilities offline (Plan B1).

**Depends on [[retire-facility-table]] B1** — the offline geo stamp — so deleting `build-gold`'s WFS
merge does not degrade `/swim` distance.

## Design (signature altitude)

- **One builder.** `swimzh build` (offline) is the sole path to a gold row; network commands
  (`scrape-gold`, `scrape-lanes`, `build-catalog`) *layer onto* it. The parallel `build-gold`
  raw→silver→gold pipeline is deleted.
- **Geo provenance = committed WFS catalog.** WFS coordinates live in the committed, reviewable
  `data/catalog.json` (regenerated by `build-catalog`), stamped onto facilities in the offline build.
  No live WFS merge at gold-build time. A future scheduled refresh, if ever wanted, returns as an
  additive `refresh` skin — never a resurrected split-brain pipeline (open-question #2).
- **Lossless-cutover guard survives the deletion.** `tests/data/test_identity_crosswalk.py` currently
  proves lossless legacy-id resolution via `registry.resolve_name`; it must be rewritten to assert off
  the `pool_alias` table BEFORE `resolve_name` is deleted.

## Out of scope

- `attach_lane_plans` (KEEP — the live lane-plan path).
- `build-catalog` (KEEP — regenerates the committed `catalog.json`).
- Snapshots / `refresh`/`verify` two-phase (#6b) and Dagster (#6c) — additive, not part of this
  deletion.
